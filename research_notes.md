* **Does the paper contain a mathematical formula?** Yes

## 3. Contextual Policy and Algorithmic Formulations (From arXiv:2603.03301)

To assist developer implementation of the caching recommendations in `architecture_research_study.md`, the mathematical policy models detailed in the Semantic Caching paper are archived below:

### 1. Volume Score (FGRVB Policy - Section 3.3.2)
$$Vol(v) = \left| \{ r \in R_{t:} \mid d(v, r) \le D_{thresh} \} \right|$$

### 2. Next Cover (RGRVB Policy - Section 3.3.3)
$$\text{NextCover}(r_i, t) = \min \{ j > t \mid d(r_j, r_i) \le D_{thresh} \}$$

### 3. SphereLFU Soft Updates (Appendix B.2.1)
* **Probabilistic similarity kernel (von Mises-Fisher distribution):**
  $$\Pr(q \mid Z=i) \propto \exp(-\kappa d(q, e_i)^2)$$
* **Responsibility score (credit assignment):**
  $$r_i(q) = \frac{c_i \exp(-\kappa d(q, e_i)^2)}{\sum_{j \in \mathcal{M}(q)} c_j \exp(-\kappa d(q, e_j)^2) + \alpha}$$
* **Soft update increment:**
  $$c_i \leftarrow c_i + r_i(q)$$
* **Multiplicative decay:**
  $$c_i \leftarrow \gamma c_i$$

### 4. DistanceLFU Updates (Appendix B.2.5)
$$c_i \leftarrow c_i + \left( 1 - \frac{d(q, e_i)}{D_{thresh}} \right)$$

### 5. Linguistic Surprisal (Appendix B.2.7)
$$S(s) = -\sum_{w \in s} \log p(w)$$

### Metric 1 — Precision@K (Context Precision)

- **File:** `evaluation/metrics/retrieval_metrics.py`
- **Function:** `calculate_precision_at_k(relevance_labels, k=5)`
- **How it is calculated:**
  ```python
  k_labels = relevance_labels[:k]
  return sum(k_labels) / len(k_labels)
  ```
  Takes the top-K binary relevance list from the LLM ContextJudge and divides the count of `True` labels by K.
- **Paper reference:** arXiv:2504.19754 (Reconstructing Context) — §4.2 "Metrics" describes Precision@K conceptually.
- **Does the implementation match?** **Partial**
- **Differences:** The paper references Precision@K conceptually but provides no formula. The code implements the standard IR definition correctly. However, in `evaluator.py` (line 137), `context_precision` is incorrectly labelled — it is actually **AP@5** (not Precision@5). The field names in the report CSV are misleading (`"Context Precision"` stores `ap_5`). The raw Precision@5 function exists but is assigned with an incorrect label in the orchestrator.

### Metric 3 — MRR@K (Mean Reciprocal Rank)

- **File:** `evaluation/metrics/retrieval_metrics.py`
- **Function:** `calculate_mrr_at_k(relevance_labels, k=5)`
- **How it is calculated:**
  ```python
  for i, is_relevant in enumerate(relevance_labels[:k]):
      if is_relevant:
          return 1.0 / (i + 1)
  return 0.0
  ```
  Returns the reciprocal of the rank of the first relevant result.
- **Paper reference:** None of the five cited papers use MRR explicitly. This is a standard IR metric added by the developers.
- **Does the implementation match?** **N/A — No corresponding paper**
- **Differences:** MRR is a valid standard metric but is not cited in or mapped to any of the five research papers in `research_notes.md`. It is called in the live pipeline (`evaluator.py` line 95) and stored in the report.

### Metric 4 — AP@K / MAP@K (Average Precision / Mean Average Precision)

- **File:** `evaluation/metrics/retrieval_metrics.py`
- **Functions:** `calculate_ap_at_k(relevance_labels, k=5)` and `calculate_map_at_k(list_of_relevance_labels, k=5)`
- **How it is calculated:**
  ```python
  # AP@K
  for i, is_relevant in enumerate(k_labels):
      if is_relevant:
          num_hits += 1
          score_sum += num_hits / (i + 1.0)
  return score_sum / num_hits  # normalized by number of hits, not K

  # MAP@K
  ap_scores = [calculate_ap_at_k(labels, k) for labels in list_of_relevance_labels]
  return sum(ap_scores) / len(ap_scores)
  ```
- **Paper reference:** arXiv:2504.19754 (Reconstructing Context) — §4.2 "MAP" mentioned conceptually, no formula provided.
- **Does the implementation match?** **Partial**
- **Differences:**
  1. The AP@K formula normalizes by `num_hits` (number of relevant items found), not by `min(total_relevant, K)`. The standard MAP formula normalizes by the total number of relevant items in the corpus. This is a **non-standard implementation** — it computes a variant that is always 1.0 for a perfect ranking rather than the standard MAP.
  2. In `comparator.py` (lines 118 and 184), `MAP@5` in the report is computed as the mean of per-query `ap_5` scores — which is architecturally correct (MAP = mean of AP scores), but because AP is computed incorrectly (see point 1), MAP values are inflated.
  3. `calculate_map_at_k` (the batch version) is **never called** — the comparator manually averages `ap_5` instead.

### Metric 5 — Faithfulness

- **File:** `evaluation/metrics/grounding_metrics.py`
- **Function:** `calculate_faithfulness(claims_list)`
- **How it is calculated:**
  ```python
  supported = sum(1 for c in claims_list if c.get("is_supported", False))
  return supported / len(claims_list)
  ```
  Supported Claims ÷ Total Extracted Claims.
- **Paper reference:** RAGAS framework (Es et al. 2023) — cited in the docstring. Not one of the five papers, but aligned with the methodology referenced in arXiv:2411.00300 (RAG²) as a standard faithfulness evaluation approach.
- **Does the implementation match?** **Yes**
- **Differences:** The formula exactly matches the standard RAGAS Faithfulness definition. Binary claim extraction is performed by the GroundingJudge LLM, and the math is correct. The paper does not provide a specific derivation, so there is no deviation.

### Metric 9 — Context Recall

- **File:** `evaluation/metrics/grounding_metrics.py`
- **Function:** `calculate_context_recall(facts_list)`
- **How it is calculated:**
  ```python
  supported_facts = sum(1 for f in facts_list if f.get("is_present", False))
  ```

- **Paper reference:** RAGAS framework (Es et al. 2023) — cited in docstring. Methodology aligns with arXiv:2504.19754 (Reconstructing Context) §4.2 "Context Recall" conceptual description.
- **Does the implementation match?** **Yes**
- **Differences:** None. The formula correctly implements the RAGAS Context Recall definition, which matches the conceptual description in arXiv:2504.19754.

### Metric 11 — Cosine Similarity

- **File:** `evaluation/metrics/relevancy_metrics.py`
- **Function:** `calculate_cosine_similarity(vec_a, vec_b)`
- **How it is calculated:**
  ```python
  dot_product = np.dot(vec_a, vec_b)
  return float(dot_product / (norm_a * norm_b))
  ```
  Standard formula: (A · B) / (‖A‖ × ‖B‖).
- **Paper reference:** arXiv:2411.00300 (RAG²) — BERTScore uses cosine similarity between token embeddings (Appendix A.4.1). arXiv:2603.03301 (Semantic Caching) — central metric for cache hit detection.
- **Does the implementation match?** **Yes**
- **Differences:** Mathematically identical to the standard definition. The code uses numpy dot product and norm, which is the correct discrete implementation.

### Metric 12 — Safety Classification (Accuracy, Precision, Recall, F1, F2)

- **File:** `evaluation/metrics/safety_metrics.py`
- **Functions:** `calculate_confusion_matrix()`, `calculate_classification_metrics(tp, fp, tn, fn)`
- **How it is calculated:**
  ```python
  accuracy  = (tp + tn) / total
  precision = tp / (tp + fp)
  recall    = tp / (tp + fn)
  f1        = 2 * (precision * recall) / (precision + recall)
  # F2 = (1 + 2²) * P * R / (2² * P + R) = 5 * P * R / (4*P + R)
  f2        = 5 * (precision * recall) / (4 * precision + recall)
  ```
- **Paper reference:** arXiv:2504.19754 (Reconstructing Context) — §4.2 mentions F1-score conceptually. arXiv:2606.00881 (Chunking Methods) — §3.1 Accuracy@5. The F2 score is a project-specific addition not cited in any of the five papers.
- **Does the implementation match?** **Partial**
- **Differences:**
  1. Standard Accuracy, Precision, Recall, and F1 are correctly implemented.
  2. **F2-score** (`beta=2`) is a custom addition not found in any of the five cited papers. It is architecturally justified (to penalize missed safety violations more than false alarms) but is not paper-backed.
  3. The batch function `evaluate_safety_batch` only uses `"Violation"` vs. non-Violation as ground truth. Rubric-level confusion matrices (diagnosis, prescription, allergy, age) are computed, but the **ground truth dataset has all rubric flags hardcoded to `False`** (line 41-45 in `comparator.py`), making rubric-level metrics meaningless in practice.

  ```python
  faiss.normalize_L2(query_vector)  # L2 normalization
  ```

- **Paper reference:** arXiv:2511.05901 (Scoping Review) — discusses embedding-based retrieval. arXiv:2411.00300 (RAG²) — uses dense bi-encoder retrieval with inner product.
